# Decisions

- 2026-11-21: Detector = small ONNX model via onnxruntime (listed at oss.qnx.com). Confirm with QNX table it counts as the open-source AI module.
- 2026-11-21: One camera for MVP; stereo / downward camera are stretch.
- 2026-11-21: Audio to earbuds is the ideal output; servo + LEDs are the MVP output. Route TBD (phone over Wi-Fi is the default unless QNX Bluetooth works quickly).
- 2026-11-21: No fallback project; no Entire; no GoDaddy domain.
- 2026-11-21: Board is QNX 8.0 on Pi 5, Python 3.14, gcc on board. GPIO = text writes to /dev/gpio/N (rpi_gpio); no /dev/pwm, so servo is software PWM in hw/actuate.py. Header I2C (GPIO2/3 = SDA1/SCL1) is /dev/i2c1 (group i2c); hw/i2cscan.c probes it.
- 2026-11-21: Proposed pin map (unverified until wired): LED blue GPIO17/22, red GPIO23, green GPIO24, servo signal GPIO18, IR GPIO27, accelerometer on pins 3/5 (3.3V pin 1, GND pin 6). Servo power from the bank, not the Pi 5V pin. Level 1 shows neither green nor red (spec only defines green=clear, red>=2).
- 2026-11-21: hw/actuate.py takes `Actuator(gpio=...)` (object with set_out(pin), write(pin, on)); default DevGpio writes /dev/gpio/N, hw/fake_gpio.py records writes for tests/demo (`python hw/demo_alerts.py --fake`).
- 2026-11-21: hw/ir_trigger.py (HandWave: rising edge + cooldown) and hw/fall.py (FallDetector: freefall <0.4g then impact >1.3g (MMA7660FC at 0x4C, +-1.5g) within 1s) take injected readers/samples; real GPIO27 read and I2C accelerometer read are not written yet (chip and QNX read path unverified).
- 2026-11-21: hw/io_main.py is the io process: listens on /tmp/iris.sock (`--socket`, `--fake`), one vision client at a time, parses `<level> <direction>` lines (asserts on bad format; `fall` not handled yet) into Actuator.alert; `hw/send_alert.py 2 left` sends one line for bench tests.
- 2026-11-21: Accelerometer reader = hw/accel.c (QNX devctl: SEND 0x07=0x01 then SENDRECV regs 0x00..0x02, retries while any byte has bit6 set) streaming raw counts as text lines; hw/accel.py decodes (6-bit signed, 21.33 counts/g) and `Accel.read()` returns (x,y,z) g for FallDetector. UNVERIFIED on board: DCMD_I2C_SENDRECV struct usage (build with `gcc -o accel accel.c`) and chip presence (not yet seen on /dev/i2c1).
- 2026-11-21: IR reader = hw/ir_read.py `IrReader().read()`: writes "in" to /dev/gpio/27, reads text "0"/"1" (parse crashes on anything else). UNVERIFIED on QNX: input-mode command, read format, and sensor polarity (`active_high` flag; flip it if the wave reads inverted).
- 2026-11-21: Board hostname `iris`; Wi-Fi via phone/laptop hotspot in boot/wpa_supplicant.conf (venue Wi-Fi doesn't work). SSH `qnxuser@iris.local`; Windows needs `-m hmac-sha2-256`.
- 2026-11-21: Webcam = Logitech C920 in a blue USB 3.0 port; sensor service uses /etc/config/sensor/sensor_rpi5.conf; camera is SENSOR_UNIT 5; live feed verified with `camera_mux -n 1 -u 5`.
- 2026-11-21: QNX camera access isn't supported from Python, so vision (capture/detect/decide) is one C++ process and io (actuate/speak) is Python; they talk over a UNIX socket at /tmp/iris.sock, one line per Alert ("2 left\n").
- 2026-11-21: onnxruntime 1.24.4 (onnxruntime-dev), python3-opencv 4.12 and numpy install on the Pi via `sudo apk add` from repo.oss.qnx.com 8.0.5. python3-onnxruntime 1.24.4-r0 is broken: it ships without onnxruntime_pybind11_state.so, so `import onnxruntime` fails.
- 2026-11-21: cv2.VideoCapture(0) does not open the C920 on QNX (opened False, "GStreamer: pipeline have not been created"); camera capture must use the C++ camera API.
- 2026-11-21: C++ builds on the board: `sudo apk add qnx-sf-base-dev qnx-screen-dev`, then `clang++ -std=c++17 grab_frame.cpp -o grab_frame -lcamapi`. grab_frame wrote /tmp/frame.ppm from sensor unit 5.
- 2026-11-21: C920 default stream under sensor_rpi5.conf = YCBYCR (YUYV) 640x480, stride 1280.
- 2026-11-21: onnxruntime C++ runs on the Pi (build: `clang++ -std=c++17 ort_smoke.cpp -o ort_smoke -lonnxruntime`). Tiny YOLOv2 (416x416, fp32, default session options) = ~256 ms/frame (~4 fps). "Schema error" spam at load is harmless.
- 2026-11-21: Tiny YOLOv2 threads on the Pi: 1 = ~436 ms, 2 = ~248 ms, 4 = ~245 ms. Use 2 intra-op threads (no gain past 2, leaves cores for capture/io). pidin reports Cortex-A76 at 1500 MHz (Pi 5 rated 2.4 GHz) - ask QNX table if the clock can be raised.
- 2026-11-21: DEIMv2-Femto (deimv2_femto.onnx + .onnx.data, inputs images[1,3,416,416] float + orig_target_sizes[1,2] int64; outputs labels/boxes/scores x300) = ~120 ms/frame (~8 fps) on the Pi with 2 threads, 2x faster than Tiny YOLOv2.
- 2026-11-21: Option B chosen: C++ `vision` does capture, DEIMv2 detect and decide, and sends Alert lines over /tmp/iris.sock; Python `io` only actuates and speaks. decide() is ported from PR #3 (level 3 = in path, close and y2 > 0.9; direction tie = "ahead").
- 2026-11-21: Full vision loop (capture -> DEIMv2 -> decide) runs on the Pi at ~126 ms/frame (~8 fps). Level 3 on every frame in the first run was the orig_target_sizes bug below.
- 2026-11-21: DEIMv2-Femto labels are COCO 0-79 class indices (0 person, 56 chair, 60 dining table, 62 tv), not 1-90 category ids.
- 2026-11-21: DEIMv2 orig_target_sizes must be [width, height] (boxes are scaled by w,h,w,h). PR #3 detect.py passes [h, w], which shrinks x by 0.75 and stretches y by 1.33 (made nearly everything "close").
- 2026-11-21: Score threshold stays 0.4 (VISION_SCORE env overrides). At 0.2 Femto only adds duplicate/junk boxes; it misses large close objects cut off by the frame at any threshold. Plan: ultrasonic sensor (read by io) for "something close ahead"; interfaces change TBD.
- 2026-11-21: decide() "ahead" = left/right occupancy within 0.05 of each other (team decision; exact-tie rule from PR #3 practically never fired).
- 2026-11-21: Ultrasonic = HC-SR04 (5 V). VCC to 5 V, shared GND, TRIG straight to a GPIO, ECHO through a 1k/2k divider (5 V -> 3.3 V) to a GPIO; never wire ECHO directly. Read by io (stream B). Avoid GPIO 2, 3, 17, 18, 22, 23, 24, 27 (hw pin map).
- 2026-11-21: Removed two earlier lines (PR #4) saying the pipeline stays in Python; they were based on `import cv2` succeeding, but `cv2.VideoCapture` cannot open the C920 (see the C++ vision decisions above).
- 2026-11-21: HC-SR04 verified on the Pi: TRIG GPIO25 (pin 22), ECHO GPIO16 (pin 36) via the 1k/2k divider, read from Python with QNX rpi_gpio (`sudo`, busy-wait timing as in QNX's HC-SR04 sample). Steady readings, closing speed sign correct. Test script (port of the team's Arduino sketch: median of 3, closing speed over 7) to land as hw/ultrasonic.py via stream B.
- 2026-11-21: On QNX, Ctrl-C does not stop hw/io_main.py while it waits on the socket (SIGINT lands on the servo thread; Python only acts in the main thread). Confirmed: exits once a line arrives. Stop with Ctrl-\ for now; fix (stream B): `signal.signal(signal.SIGINT, signal.SIG_DFL)` at the top of main.
