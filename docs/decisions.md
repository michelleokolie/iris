# Decisions

- 2026-11-21: Detector = small ONNX model via onnxruntime (listed at oss.qnx.com). Confirm with QNX table it counts as the open-source AI module.
- 2026-11-21: One camera for MVP; stereo / downward camera are stretch.
- 2026-11-21: Audio to earbuds is the ideal output; servo + LEDs are the MVP output. Route TBD (phone over Wi-Fi is the default unless QNX Bluetooth works quickly).
- 2026-11-21: No fallback project; no Entire; no GoDaddy domain.
- 2026-11-21: Board is QNX 8.0 on Pi 5, Python 3.14, gcc on board. GPIO = text writes to /dev/gpio/N (rpi_gpio); no /dev/pwm, so servo is software PWM in hw/actuate.py. Header I2C (GPIO2/3 = SDA1/SCL1) is /dev/i2c1 (group i2c); hw/i2cscan.c probes it.
- 2026-11-21: Proposed pin map (unverified until wired): LED blue GPIO17/22, red GPIO23, green GPIO24, servo signal GPIO18, IR GPIO27, accelerometer on pins 3/5 (3.3V pin 1, GND pin 6). Servo power from the bank, not the Pi 5V pin. Level 1 shows neither green nor red (spec only defines green=clear, red>=2).
- 2026-11-21: hw/actuate.py takes `Actuator(gpio=...)` (object with set_out(pin), write(pin, on)); default DevGpio writes /dev/gpio/N, hw/fake_gpio.py records writes for tests/demo (`python hw/demo_alerts.py --fake`).
- 2026-11-21: hw/ir_trigger.py (HandWave: rising edge + cooldown) and hw/fall.py (FallDetector: freefall <0.4g then impact >1.3g (MMA7660FC at 0x4C, +-1.5g) within 1s) take injected readers/samples; real GPIO27 read and I2C accelerometer read are not written yet (chip and QNX read path unverified).
- 2026-11-21: hw/io_main.py is the io process: listens on /tmp/iris.sock (`--socket`, `--fake`), one vision client at a time, parses `<level> <direction>` lines (asserts on bad format; `fall` not handled yet) into Actuator.alert; `hw/send_alert.py 2 left` sends one line for bench tests.
- 2026-11-21: Accelerometer reader = hw/accel.c (QNX devctl: SEND 0x07=0x01 then SENDRECV regs 0x00..0x02, retries while any byte has bit6 set) streaming raw counts as text lines; hw/accel.py decodes (6-bit signed, 21.33 counts/g) and `Accel.read()` returns (x,y,z) g for FallDetector. UNVERIFIED on board: DCMD_I2C_SENDRECV struct usage (build with `gcc -o accel accel.c`) and chip presence (not yet seen on /dev/i2c1).
- 2026-11-21: IR reader = hw/ir_read.py `IrReader().read()`: writes "in" to /dev/gpio/27, reads text "0"/"1" (parse crashes on anything else). UNVERIFIED on QNX: input-mode command, read format, and sensor polarity (`active_high` flag; flip it if the wave reads inverted).
- 2026-11-21: Board hostname `iris`; Wi-Fi via phone/laptop hotspot in boot/wpa_supplicant.conf (venue Wi-Fi doesn't work). SSH `qnxuser@iris.local`; Windows needs `-m hmac-sha2-256`.
- 2026-11-21: Webcam = Logitech C920 in a blue USB 3.0 port; sensor service uses /etc/config/sensor/sensor_rpi5.conf; camera is SENSOR_UNIT 5; live feed verified with `camera_mux -n 1 -u 5`.
- 2026-11-21: QNX camera access isn't supported from Python, so vision (capture/detect/decide) is one C++ process and io (actuate/speak) is Python; they talk over a UNIX socket at /tmp/iris.sock, one line per Alert ("2 left\n").
- 2026-11-21: onnxruntime 1.24.4 (onnxruntime-dev), python3-opencv 4.12 and numpy install on the Pi via `sudo apk add` from repo.oss.qnx.com 8.0.5. python3-onnxruntime 1.24.4-r0 is broken: it ships without onnxruntime_pybind11_state.so, so `import onnxruntime` fails.

- 2026-11-21: Servo signal moved from GPIO18 to GPIO5 (physical header pin 29; pin 30 beside it is a ground pin) because physical pins 12, 14, 11 (GPIO17) and 21 (GPIO9) were taken or crowded; the gpio driver accepts `out` on it. The servo (an SG92R with blue/red/yellow wires, not the usual brown/red/orange) is powered from its own breadboard module fed by the power bank; ground is shared by a jumper between the two breadboards' ground rails, and the signal goes through a 1 kOhm series resistor as protection while the wire roles are unconfirmed (assumed: red = +5 V, blue = ground, yellow = signal). hw/bench.py `servo [rest_us tap_us]` defaults to a gentle 1400/1600 us swing for the first test; io's own taps use actuate.REST_US/TAP_US (1000/1800, about 140 degrees, to be tuned to the arm). - 2026-11-22: FOUND on the Pi: time.sleep rounds up to the 1 ms QNX system tick (1.0 ms took ~2.0, 1.4 and 1.6 ms both took 2.0, 2.0 took 3.0), so the sleep-timed servo pulses could not tell rest (1.0-1.4 ms) from tap (1.6-1.8 ms) and the first bench test (1400/1600 us) sent the same 2 ms pulse both ways; the servo did not move. Fix: hw/actuate.py `_pulse` busy-waits the pulse width on time.perf_counter (sleep is still used for the 19 ms gap). Measured on the Pi without touching a pin: widths 1002/1402/1601/2002 us for 1000/1400/1600/2000 asked, period about 21 ms (the two write calls, not the pin edges). The busy wait holds the GIL for up to 2 ms per 21 ms while tapping; a C helper stays the fallback if jitter shows up on the servo.
